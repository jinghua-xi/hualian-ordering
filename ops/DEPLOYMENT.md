# 本地到优云的一条命令部署

本机保存的是可编辑的项目源码和本地测试数据；目前没有制作网站的 Docker 镜像。网站只依赖 Python 标准库，继续使用优云现有的 Python 环境和 Ollama 即可。

在本地终端执行：

```sh
cd "/Users/huasmac/Ordering Website"
./deploy
```

服务器必须已开机，SSH 端口映射应有效。部署工具不会自动启动收费实例，也不会关闭实例。

## 每次会执行什么

1. 验证本地 Python 语法、商品目录和源码清单。
2. 使用 SSH 密钥和固定服务器公钥建立一条连接，后续上传和远程执行均复用它；首次临时握手失败最多重试三次。上传到独立暂存目录。
3. 校验每个文件的 SHA-256，在订单库副本上预检新版初始化。
4. 备份旧源码和订单库；等待正在发送的邮件完成后，停止网站进程。
5. 更新源码并重启网站；检查新进程、登录页、目录、服务器时间、销售订单查询、静态资源和 Ollama 中的 Qwen3-8B。
6. 在本机检查公网入口。只有全部通过才显示部署完成。

该流程不会创建测试订单，也不会发测试邮件。更新后的服务仍会照常处理已有邮件队列。

## 哪些数据不会上传覆盖

上传白名单包含 `server.py`、`order_delivery.py`、`catalog.json`、网页资源、`ops` 中的 Python/Shell 脚本和部署入口。不会上传本地测试订单库、`preview.env`、日志、密钥、缓存或历史报告。

线上账号、SMTP 配置和真实订单留在 `/workspace/ordering-preview`。Qwen 模型继续使用服务器上已有的文件，不会重复下载。

## 本机连接配置

私有部署文件放在项目的 `.deploy/` 中，该目录已排除出 Git 和上传包：

- `config.json`：SSH 主机、映射端口、用户名、远端目录和公网地址。
- `id_ed25519`：本机部署私钥，权限必须为 `600`。
- `known_hosts`：已核实的服务器 SSH 公钥。
- `last-manifest.json`：最近一次成功发布的文件校验清单。

首次配置时生成专用 SSH 密钥，将公钥加入该实例的 `authorized_keys`，并通过已登录的 Jupyter 终端核实服务器主机公钥。私钥不上传到服务器。不要把服务器密码或 Gmail 应用密码写入部署脚本。

配置格式：

```json
{
  "host": "cpod-1xdwqzrhaexo.podtcp.compshare.cn",
  "port": 29134,
  "user": "root",
  "project_root": "/workspace/ordering-preview",
  "public_url": "https://8767-cpod-1xdwqzrhaexo.pod.compshare.cn/",
  "identity_file": "id_ed25519",
  "known_hosts_file": "known_hosts"
}
```

这里的端口是已有记录中的 SSH 映射端口；首次连接或平台调整映射后，请以优云控制台显示的当前值为准。不要用 Jupyter 的 8888 端口或网站的 8767 端口代替 SSH 端口。

## 检查与失败处理

只检查本地文件、不上传：

```sh
./deploy --dry-run
```

预检不通过时旧服务继续运行。源码切换后检查失败，云端助手会尝试恢复上一版源码并重启。回退时保留当前订单库，避免抹掉刚提交的订单或发信结果。数据库备份供人工恢复，不会自动覆盖真实数据。最近三次成功发布的备份保存在服务器 `releases/` 中。

如果本机网络中断或公网检查失败，不要直接判断发布已回退；先打开公网网站，核对线上状态后再重试。工具明确报告非零退出码，不会将失败显示为发布成功。

后续若引入第三方 Python 包或破坏性数据库迁移，需要一并更新部署流程；当前命令适用于现有的标准库网站结构。

SSH 随机断开的诊断与配置修复见 [修复记录](SSH-REPAIR.md)。该修复使用原23端口服务，不新增SSH监听端口。
